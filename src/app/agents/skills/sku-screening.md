# sku-screening

> 按部门/品类做多维度量化筛选，输出「缺货、断码、积压、滞销」候选清单（先筛后判，省一次 LLM）。

## 适用场景
- 用户问「最近有哪些款需要重点关注 / 帮我筛一批异常款 / 男装这周有什么风险」。
- 批量巡检前的候选集生成（与 `POST /api/patrol` 的 screening 同一套阈值）。

## 步骤
1. 确认范围：部门（默认取当前账号部门）→ 品类 → 时间窗（默认近 7 天）。
2. 调 `get_sales_rate(department)` 看整体动销，再对候选 SKU 逐个取 `get_sku_metrics`。
3. 按下面的量化阈值打标：`断码 / 缺货 / 积压 / 滞销`，多标签可叠加。
4. 只对打标的 SKU 做 LLM 研判（不要全量送模型）。

## 取数工具
- `get_sales_rate`、`get_sku_metrics`、`get_inventory`、`get_sales`

## 判定阈值（**候选初筛口径**，与 `pipeline/screening.py` 一致）
- 缺货：可供天数 ≤ 7 天。
- **断码（仅初筛）**：同款零库存尺码数 ≥ 2 —— 只用它"挑出值得深看的款"；
  **对外下断码结论必须走 `size-gap-diagnosis` 的主销码口径**（主销码 = 30 天占比 ≥15%，
  断码 = 主销码可用为 0；长尾码缺货不算断码）。
- 积压：可供天数 ≥ 60 天（≥90 天直接判定）；滞销：近 7 天日均 < 3 件。
- 趋势下滑：归一化斜率 ≤ −0.45 且 R² ≥ 0.55。

## 输出模板
| SKU | 品类 | 标签 | 关键指标 | result_id |
依次列候选，最后一行给「共 N 款，建议优先处理 X 款」。
